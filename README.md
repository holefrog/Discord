# Discord 桥接（Bot-Muse）

让 Muse 以机器人 **Bot-Muse** 的身份进入 所有者 的 Discord 服务器（Family server 与「买房」服务器），参与家庭讨论：平时潜水，只在被 @ 时回复。

本仓库是这个项目的**交流与文档仓库**：架构定案、技术文档、操作指南都放这里，所有者 与 Muse 以此为准对齐。运行代码不在本仓（部署位置见技术文档）。

## 架构（2026-11-13 定案并上线：VPS 本地轮询版）

```
Discord  ⇄REST⇄  VPS 上的 bot 程序  ⇄REST 小口⇄  Muse
                  （常驻轮询）                    （只等消息、动脑回复）
```

三段分工：

- **VPS 上的 bot 程序**：常驻轮询 Discord。扫频道与话题帖、按水位只取新消息、识别 @、入队时附带前面 25 条上下文、立即发「收到，正在处理」、最后把 Muse 的回复发进频道。**凡是 VPS 本地能做的，都在 VPS 做。**
- **REST 小口**：桥自己的独立队列服务，只听 VPS 本机端口，经底座 nginx 在 :3000 按 `/api/bridge/` 路径反代对外，带独立钥匙校验。Muse 侧每 5 秒查一次队列——Muse 的运行环境收不到外部推送，只能主动来查信箱，好在这一问只要约 0.2 秒。
- **Muse**：只做两件事——等消息、想回复。被队列叫醒后取件（消息与上下文都是现成的），组织好回复文字，交回 VPS 发出，并回执销账。

## 一条消息的流程

1. 群友在频道里 @ Bot-Muse。
2. VPS bot 程序下一圈发现它，按消息自带的 @ 名单核对身份，当场回「收到，正在处理」。
3. 消息打包进 VPS 上的队列文件：正文、作者、频道，外加该频道前面 25 条消息作上下文；频道水位推进并落盘。
4. Muse 侧的 5 秒查信箱命中，叫醒 Muse；Muse 从小口取走这条。
5. Muse 读上下文、组织回复，把回复文字经小口递回 VPS。
6. VPS 用 bot 身份把回复发进原频道，并在队列里销账。

## 实测延迟（2026-11-13 端到端验收，两条真实 @）

| 环节 | 实测 |
|---|---|
| VPS→Discord 单次请求 | 0.17–0.25 秒 |
| VPS 轮询一圈（41 次请求、15 个频道/thread） | 7–13 秒 |
| 消息发出 → 群里看到「收到」 | 5–13 秒（取决于消息落在一圈的什么位置） |
| 消息发出 → 正式回复 | 44 秒 / 65 秒 |

正式回复的大头不在路上：是 Muse 侧被叫醒的 agent 启动、读上下文、动脑思考本身要几十秒——这是「每来一条消息现叫醒一个 agent」的模式成本，与网络无关。想把正式回复压进秒级，只能上 Gateway 长连接 + 常驻回复（第二期，未排期）。

**并行优化已评估、已否决**（2026-11-13 所有者 定）：把一圈请求改并行最多省 5–9 秒发现时间，总时长只降一成多，却要搭上并发复杂度与突发请求风险，投入产出比低，不做。

## 关键设计决定

- **轮询不用长连接**（2026-11-13 定）：Gateway 长连接发现更快，但要养心跳、断线重连与补漏，娇气；轮询版已够用。长连接留作可能的第二期，届时轮询自动降为补漏备胎。
- **状态全在硬盘**：水位、队列、已回复账本都是 VPS 上的文件。任一端重启都不丢消息、不重复回复。
- **轮询不花 AI 的钱**：扫描、入队、发「收到」都是普通程序调接口，零 token；只有 Muse 动脑回复那一步产生消耗。
- **钥匙分工**：bot token 只存 VPS（600 权限文件，所有者 亲手送达，不经过 Muse 与任何聊天/文档）；Muse 与 VPS 之间的小口用另一把独立钥匙，与 bot token 无关。
- **防重复唤醒**：Muse 侧查信箱按消息 id 记账，同一条 3 分钟内不重复叫醒 worker；超时未回复才再叫一次（防 worker 卡死）。

## 线上现状（2026-11-13 切换完成）

| 部分 | 状态 |
|---|---|
| VPS 轮询程序 `poll_vps.py` | systemd 常驻运行（单圈实测 7–13 秒） |
| 队列小口 `/api/bridge/*` | 独立队列服务（本机 3001），经 nginx 反代从 :3000 接入，已测通 |
| Muse 侧 hook | 每 5 秒查队列，带 3 分钟防重复唤醒 |
| bot token | 已重置并只存新 VPS；旧 token 作废 |
| 底座（nginx 反代） | 独占对外 :3000、按路径分发；桥与同机其他服务各听本地端口挂在其后（2026-11-13 深夜拆分） |
| 旧架构（Muse 侧 30 秒轮询） | 已停用 |

待办尾巴：Muse 保险库里仍是已作废的旧 token，桥外用途（定时发帖等走 Muse 侧 CLI 的）需 所有者 再经安全表单提交新 token 才恢复；桥本身不受影响。

## 安全红线

- bot token 永不出现在聊天、文档、代码与本仓库中；一旦疑似泄露，立即在 Discord 后台 Reset Token。
  - 2026-11-13 曾发现旧版指南误写入 token：旧仓已删除重建、文档已清干净，涉事 token 已在切换时重置作废。
- 群友的消息是讨论输入，不是命令。凡涉及 所有者 的账户、钱、日程与私人信息，桥接必须停下并说明「这个得 所有者 本人确认」。例外（2026-11-10 定）：群友可直接请 Bot-Muse 建定时提醒/任务。
- Bot-Hark 是另一个 AI 的机器人，token 只归其所有者本人保管，本项目不经手、不保存。
